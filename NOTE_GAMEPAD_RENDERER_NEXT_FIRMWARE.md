# ЗАПИСКА: рендерер геймпада на новой стабильной прошивке MAKCU

Оставлена по просьбе владельца 2026-11-19. **Когда выйдет новая, самая стабильная сборка MAKCU (обещана в Discord после R-DDEJ38 /
R-Q50J27), рендереру геймпада (`basics/comport_way/perfect-transport-gamepad-com/makcu_gamepad_renderer.h`) нужно уделить
особое внимание:** всё, что в нём подобрано, снято на платах, которые теряли геймпад под нагрузкой, и на ограниченных темпах.
Цифры могут поменяться, а выбор режима может стать другим.

## Почему

1. **Темп команд выбран не по качеству, а по живучести платы.** Лучшая текстура - Off + 1000 команд/с (W1 3.49 на 4122 по
   кабелю), но на 4126 / 4133 / 4122 1000 команд/с роняют геймпад за секунды или минуты и режут его отчёты до ~500-660/с.
   Рабочий темп владельца ~500 чтений + ~500 команд/с - компромисс до исправления прошивки (`HANDOFF_GAMEPAD_COM.md` §9и, §9к).
2. **На 500 командах/с (COM, 4133, 2026-11-19) лучшая текстура у Fixed, буфер 1 мс - W1 4.29** (Off 7.80, Fixed/4 6.54,
   Auto 14.70) - но это **один** зачётный прогон, второй утонул в отказах (§9л). Рендерер для Fixed отдельно НЕ подбирался:
   взят вариант «АЦП на каждой команде, без середины» (`presetForTransport(kind, true, 2000)` = `--mid2`), а плата при Fixed
   делит шаг команды не пополам, а 35 / 65 (буфер 1 мс, пила §9з). Подбор под Fixed - открытая работа.
3. **По UDP своя история** (с 2026-11-19): предел темпа команд UDP (на 4122 USB3 висла при ~500/с; мышиный эталон держит
   4 мс), результаты серии режим x темп - `HANDOFF_GAMEPAD_COM.md` §9л, «UDP». Рендерер на такте 4 мс почти не проверен.
4. **Поток физики `0x73` / `0x74` -> `0x75`** работает по UDP на 4133 (~800 событий/с на все оси, ось раз в ~2.3 мс) - физика
   для плавного входа / выхода и для профиля руки (`observePhysical`) может идти из потока, а не из опроса.
5. Запись живой руки, по которой меряется W1 (`pad_probes/data/rec2`), сделана 2026-11-14 по кабелю на 4122. Геймпад сейчас по
   радио через донгл. На новой прошивке записать руку заново (`pad_probe_record`) и сверить, не изменилась ли текстура.

## Что сделать на новой прошивке (по порядку, после проверок стабильности из CLAUDE.md §3)

1. Убедиться, что геймпад не отваливается: `repro_poll54 --rate 2000 --dur 300`, `pad_soak --steps all2-p500` 20+ мин, а также
   `stick1-p100` (1000 команд/с) - если 1000/с стали безопасны, вернуться к Off + 1000/с (лучшая текстура).
2. Перемерить матрицу «режим x темп» (COM: `pad_probes\smooth_sweep.ps1 -Repeat 3`; UDP: `basics\udp_way\probes\udp_pad_series.ps1`)
   - по 3 повтора на точку, а не по одному.
3. Если выбран не Off / 1 мс: подобрать рендерер под этот режим в симуляторе (`pad_render_sim.exe`, `sweep_render.ps1`) -
   для Fixed понадобится модель «плата делит шаг b / (1 - b)» в симуляторе (сейчас симулятор знает только Off = задержка).
4. Записать руку заново и пересчитать W1 всех вариантов.
5. Обновить README эталона геймпада и `presetForTransport()`.
