# Задача: инжект MAKCU по UDP с частотой ~1000 Гц (папка basics/udp_way)

Отвечай по-русски. Коммить только по моей просьбе. Перед любым прогоном, который двигает курсор,
предупреди меня одной строкой (мышь в это время не трогаю) - и запускай, долго не тяни с
пробами "без движения". Не убивай мои процессы без спроса. Не сканируй сеть без спроса.

## Цель

Получить по UDP то же, что уже есть по COM: Raw-инжект ~1000 Гц HID (один отчёт на мс), путь
"отправлено = пришло в Windows" до отсчёта. Я уверен, что плата это умеет по UDP. Прошлый чат
пришёл к выводу "на fw 4094 по UDP потолок ~250 Гц" - мне этот вывод не кажется убедительным.
**Не верь ему на слово**: ниже факты (с командами, чтобы повторить) отдельно от интерпретаций,
и список того, что НЕ проверялось. Ищи способ, а не доказательство невозможности.

## Железо и окружение

- MAKCU, прошивка 4094 (V4.085 + стики; Raw API 0x69/0x6A есть). Мышь Logitech Lightspeed 046D:C547.
- Два ESP32-S3: host-чип (USB3: хаб UGREEN с мышью и Ethernet RTL8152) и device-чип (USB1 -> ПК),
  между ними UART 4 Мбод. COM-кабеля (USB2/CH343) сейчас НЕТ: связь только по сети.
- Плата 192.168.50.175:8080 (UDP), ПК 192.168.50.87, через свитч. ping < 1 мс.
- Toolchain: MinGW g++ (C:\mingw64\bin), Python 3.11 (pyenv), PowerShell + Git Bash.

## Что уже есть в коде (работает, проверено на железе)

- `basics/udp_way/makcu_udp_transport.h` - `RawUdpTransport : mover::Transport`: RAW-обёртка
  (0x55 + nonce 8 байт + кадр), nonce = номер датаграммы, поток приёма, SIO_UDP_CONNRESET выкл.,
  темп по ответам (`--pace reply`, по умолчанию: одна датаграмма в полёте, следующая из потока
  приёма сразу по ответу) или ведро (`--pace bucket`, `--gap-us`, `--burst`), форматы 0x69/0x6A, 0x18, 0x67, восстановление
  потерь (опрос 0x6A consume=0 для потерянного 0x69, повтор квитанций), `probeIntake()`.
- `basics/udp_way/makcu_udp_mover.cpp` + `build.bat` - стенд как у COM (меню F1-F12, --compare,
  --sweep, --run, --check, --netprobe). Общие заголовки берутся из `..\comport_way`; для этого
  интерфейс Transport вынесен в `comport_way/mover_transport.h` (COM-стенд собирается как прежде).
- `basics/udp_way/probes/*.py` - пробы прошлого чата (запуск: `python -I probes\<имя>.py`).

Интерпретация (НЕ факт): UDP-обработчик host-чипа стоп-и-ждёт - пересылает кадр через мост на

входящие датаграммы выбрасываются. Raw = 2 кадра на отчёт -> ~290 Гц максимум на 4094.

### ПРОРЫВ (сессия 3): транспорт батчится, узкое место - только опкод движения

Исходный список первой сессии:

1. **Несколько полных RAW-записей в одной датаграмме**: `55 nonceA кадрA 55 nonceB кадрB ...`
   (проверялся только один заголовок + несколько кадров). Также: кадры с выравниванием/паддингом,
   разные LEN, IP-фрагментация большой датаграммы.
2. **Режим HOST**: в SDK он по умолчанию; плата на голый кадр молчит - возможно, режим выбирается
   настройкой платы (Toolkit / app.makcu.com, сетевые настройки). Спроси меня, что видно в Toolkit
   (скриншот сетевых настроек), прежде чем что-то менять: без COM-кабеля можно потерять связь.
3. **Шифрованный UDP** (AES-128, `transport_encryption.*` в SDK, кадр 0x03): другой код на плате,
   `decodeResponses` возвращает несколько записей. Нужен ключ - спроси меня.
4. **JS-бандл Toolkit (app.makcu.com)**: прошлый COM-чат нашёл там семантику 0x1F. Поищи там
   реализацию сети/UDP: режимы, порты, пакетирование, rate, raw. Это самый недоисследованный источник.
5. **Чем именно я раньше получал 600-700 Гц по UDP** - спроси меня и/или найди в git-истории
   и старых скриптах; повтори этот метод на 4094 и посмотри, почему он быстрее 583 команд/с
   (или это интерполятор, который размножает одну команду на 2-4 отчёта).
6. Другие порты/сервисы платы, Wi-Fi - только с моего разрешения.
7. Комбинации: Raw + 0x18 (Raw ждёт опустения очереди AUTO), разные `timeout_uf`, влияние
   `km.device() M:16uf` (проверь, что мышь в G Hub на 1000 Гц).
8. Официальная поддержка: найди в доках/MCP/changelog что угодно про UDP-темп; если ничего -
   подготовь запрос в MAKCU (несколько кадров в датаграмме / пакетная квитанция Raw).

## Приёмка (как у COM)

- Raw-статистика: отправлено = в FIFO = в USB-endpoint, отказов 0, перенос (0,0), путь совпадает.
- F2: HID ~1000 Гц (99%+ интервалов 1 мс). F10: генератор = HID в каждой корзине. F4: путь совпадает.
- Потери: что видно в счётчиках, путь не теряется и не дублируется. Джиттер тиков против COM.
- Если 1000 Гц не выходит - покажи цифрами, где узкое место, но сначала закрой пункты 1-5 выше.
